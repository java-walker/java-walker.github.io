## 一、为什么需要定时任务？

在服务器运维中，很多工作需要在特定时间自动执行：

Linux提供了两大利器：crond（周期性任务）和atd（一次性任务）。

## 二、crond — 周期性定时任务

### 2.1 基本介绍

crond 是Linux的后台守护进程，负责周期性执行用户设定的任务。安装系统后默认已启动。

```
# 查看crond服务状态
```

| 
选项

功能

示例

### 2.3 时间格式（5个占位符）

```
* * * * *
```

> 💡 如果忘记了格式，可以查看 /etc/crontab 文件，里面有详细的注释说明。

### 2.4 特殊符号

| 
符号

 | 

含义

 | 

示例

 |
| --- | --- | --- |
| `*` | **任意值**

（每分钟/每小时/每天...）

 | `* * * * *`

 = 每分钟

 |
| `,` | **列举多个值** | `0 8,12,16 * * *`

 = 每天8点、12点、16点

 |
| `-` | **范围** | `0 5 * * 1-5`

 = 周一到周五的5点

 |
| `*/n` | **每隔n单位** | `*/5 * * * *`

 = 每5分钟

 |

### 2.6 ⚠️ crontab 注意事项

1\. 命令必须使用绝对路径

```
# ❌ 错误（环境变量不同，可能找不到命令）
```

为什么？crond 执行时不加载用户的环境变量（如 .bashrc），所以 ll 这类别名/简写无法识别，必须用完整路径。

2\. 脚本需要赋予执行权限

```
chmod +x /home/backup.sh
```

3\. 建议使用脚本（而非直接写命令）

```
# ❌ 不推荐：直接在crontab写复杂命令
```

## 四、crond vs atd 对比

| 
对比项

 | 

crond

 | 

atd

 |
| --- | --- | --- |
| **执行频率** | **周期性**

（多次执行）

 | **一次性**

（仅执行一次）

 |
| **适用场景** | 

定期备份、监控、清理

 | 

临时性任务、延迟操作

 |
| **配置方式** | `crontab -e`

 编辑

 | `at 时间`

 交互输入

 |
| **任务保存** | 

永久有效（直到删除）

 | 

执行后自动移除

 |
| **查看任务** | `crontab -l` | `atq` |
| **删除任务** | `crontab -r`

（删除全部）或编辑删除

 | `atrm 编号` |

## 五、常见报错与解决

| 
报错

 | 

原因

 | 

解决

 |
| --- | --- | --- |
| `command not found` | 

命令未用绝对路径

 | 

使用 `which 命令` 查看路径后修改

 |
| `crontab: command not found` | 

未安装cron

 | `yum install -y cronie`

 / `apt install -y cron`

 |
| `Can't open /var/run/atd.pid` | 

atd服务未启动

 | `systemctl start atd` |
| `你输入的文本没有结束` | 

忘记Ctrl+D退出

 | 

按 `Ctrl+D` 完成输入

 |
| `%`

 被识别为特殊字符

 | 

crontab中%有特殊含义

 | 

使用 `\%` 转义

 |
